# AeroFly — Specifications

This directory contains formal specifications that define what AeroFly should do and how.

## Specs-First Workflow

Before implementing any significant feature:
1. Write the specification in this directory
2. Create a GitHub issue referencing the spec
3. Get the plan approved
4. Then implement based on the spec

## File Naming Convention

- `10_Product_Requirements.md` — High-level product requirements
- `20_User_Stories.md` — User stories
- `30_Acceptance_Criteria.md` — Acceptance criteria per feature
- `TECHNICAL_SPECIFICATION.md` — Technical details and data models

*Specifications will be added as the project progresses.*
